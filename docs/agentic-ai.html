How the agents work

One LangGraph graph: two guardrail nodes that never call an LLM, a cheap router, three specialist agents with tools, and a memory node. Every step is checkpointed per conversation, in SQLite on your laptop and PostgreSQL on EKS.

Tools

ToolWhat it doesGuardrails
get_schemaTables, columns and the SQL dialect (SQLite or PostgreSQL)read-only connection

Guardrails, in order

question ─▶ check_input      size · prompt-injection score ≥ 0.6 · "delete/drop/update ..." commands   → refuse, no LLM call
          ─▶ system prompt    data is never instructions · read-only · no PII · canary token
          ─▶ check_sql        one statement · SELECT/WITH only · no write/admin keywords · no PII columns
          ─▶ database         read-only transaction, 60 s timeout, read-only user (RDS)
          ─▶ redact_rows      blanks email / address / IP columns (catches SELECT *)
          ─▶ wrap_tool_output flags instruction-like text found in data
          ─▶ check_output     canary → refuse · redact emails, phones, card numbers, API keys

Memory

The last 6 turns go to the model word for word. Older turns are folded by Haiku into a running summary that keeps every number, year and metric, so long chats stay cheap without forgetting. The window always starts at a user message, so a tool call is never separated from its result.
